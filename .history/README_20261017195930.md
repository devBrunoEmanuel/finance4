# Finance4

Autor: Flávio Augusto de Freitas ([@flavioaugustodefreitas](https://twitter.com/flaviofreitas))
Aplicativo mobile de controle financeiro pessoal, desenvolvido com Expo e React
Native. O Finance4 permite registrar receitas e despesas, acompanhar o saldo
total e gerenciar lançamentos em uma interface simples em português.

## Funcionalidades

- Cadastro e login com e-mail e senha.
- Sessão persistida entre aberturas do aplicativo.
- Listagem de lançamentos ordenada por data, com atualização por gesto.
- Saldo total calculado a partir das receitas e despesas.
- Cadastro e edição de lançamentos com rótulo, data, valor e tipo.
- Remoção de lançamentos pelo menu exibido ao pressionar um item.
- Valores formatados em reais (BRL).
- Execução em Android, iOS e Web.

## Configuração

1. Crie um projeto no [Supabase](https://supabase.com/) e configure a
   autenticação por e-mail e senha.
2. Na raiz do projeto, crie um arquivo `.env` com a URL do projeto e a chave
   publicável (publishable key) do Supabase:

   ```env
   EXPO_PUBLIC_SUPABASE_URL=https://seu-projeto.supabase.co
   EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sua-chave-publicavel
   ```

   Não coloque chaves secretas de servidor no aplicativo. Configure políticas
   de segurança (RLS) no Supabase para proteger os dados dos usuários.
3. Crie a tabela `accounts` no Supabase. O app espera os campos `id`, `label`,
   `date`, `value` e `type`. Uma estrutura compatível deve armazenar `id` como
   identificador, `label` como texto, `date` como data/hora, `value` como
   número e `type` como texto (`income` para receita ou `expense` para despesa).
   Configure também as permissões de leitura, inclusão, edição e remoção
   conforme as regras de acesso do seu projeto.

### Configuração do Supabase

Execute o SQL abaixo no Supabase:

```sql
create table accounts (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users not null,
  label text not null,
  date timestamptz not null default now(),
  value numeric not null,
  type text not null check (type in ('income', 'expense')),
  created_at timestamptz default now()
);

-- RLS: cada usuário só vê suas próprias contas
alter table accounts enable row level security;

create policy "Usuários veem suas próprias contas"
  on accounts for select
  using (auth.uid() = user_id);

create policy "Usuários inserem suas próprias contas"
  on accounts for insert
  with check (auth.uid() = user_id);

-- Trigger que preenche user_id automaticamente no INSERT
create or replace function public.handle_new_account()
returns trigger as $$
begin
  new.user_id := auth.uid();
  return new;
end;
$$ language plpgsql security definer;

create trigger on_account_created
  before insert on public.accounts
  for each row
  execute function public.handle_new_account();
```

### Realtime do Supabase — atualização em tempo real (bônus)

Em `accounts.tsx`, se você quer que a lista atualize automaticamente mesmo que outra pessoa/dispositivo insira uma conta, use o Realtime do Supabase. Ele escuta mudanças na tabela via WebSocket.

```tsx
import { RealtimeChannel } from '@supabase/supabase-js';

// Dentro do componente:
useEffect(() => {
  loadAccounts();

  // Inscreve em mudanças na tabela 'accounts'
  const channel: RealtimeChannel = supabase
    .channel('accounts-changes')
    .on(
      'postgres_changes',
      { event: '*', schema: 'public', table: 'accounts' },
      (payload) => {
        console.log('Mudança detectada:', payload);
        loadAccounts(); // recarrega tudo (poderia otimizar aplicando o delta)
      }
    )
    .subscribe();

  return () => {
    supabase.removeChannel(channel);
  };
}, []);
```

>**Importante**: para o Realtime funcionar, a tabela precisa ter publicação habilitada no Supabase:
>Dashboard → Database → Publications → supabase_realtime → marque `accounts`.
